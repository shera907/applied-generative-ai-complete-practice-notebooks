# 🧠 Image Question Answering (Image QA / VQA)

This notebook explains how **Vision–Language Models (VLMs) answer questions
about images**, and why this task is much harder than it appears.

You will learn:
- What Image QA actually is (architecturally)
- The difference between perception and reasoning
- Common Image QA failure modes
- Why language priors dominate visual evidence
- How to design safer Image QA systems

📌 Core principle:
> Image QA answers questions about embeddings,
> not about the real world.

## 1. What Is Image Question Answering?

Image QA is the task where a system:
- takes an image
- takes a natural language question
- produces a natural language answer

Example:
Image → photo of a street  
Question → “How many cars are parked here?”  
Answer → text generated by a VLM

## 2. Why Image QA Is Hard

Humans:
- perceive objects
- reason about relationships
- count, compare, infer

VLMs:
- encode visual patterns
- align them with language
- generate plausible text

Counting, causality, and intent
are not native capabilities.

## 3. Image QA Architecture

```text
Image
 ↓
Vision Encoder
 ↓
Visual Embeddings
 ↓
Fusion with Question Embedding
 ↓
Language Model
 ↓
Answer Text

The question strongly influences what the model "sees".
```

## 4. Question-Guided Perception

In Image QA:
- the model does NOT analyze the image independently
- the question biases attention

This means:
> The same image can produce very different “perceptions”
> depending on the question.

## 5. Language Priors

If a question matches common patterns,
the model may answer from prior knowledge
even when the image contradicts it.

Example:
“Is the sky blue?”
→ Often answered “Yes” even if the image shows night.

## 6. Counting Failure

VLMs struggle with:
- exact counts
- overlapping objects
- small or distant items

Answers like:
- “about three”
- “several”
are signs of uncertainty masked as fluency.

## 7. Spatial Reasoning

Image QA often fails at:
- left vs right
- relative positioning
- depth and distance
- occlusion reasoning

Visual embeddings are not geometry-aware.

## 8. Vision Hallucinations

Common hallucinations:
- describing objects not present
- assuming typical scenes
- filling missing details

Example:
Seeing a “plate of food” when only a table is visible.

## 9. Ambiguity

Images are ambiguous:
- occluded objects
- low resolution
- multiple interpretations

Image QA systems must:
> acknowledge uncertainty, not hide it

## 10. Question Quality Limits

Even perfect questions cannot:
- add missing pixels
- resolve occlusion
- remove visual noise

Prompting cannot fix perception limits.

## 11. Safer Output Patterns

Safer answers:
- express uncertainty
- describe visible evidence
- avoid definitive claims

Example:
“I can see two clearly visible cars; others may be occluded.”

## 12. Image QA vs OCR Pipelines

For documents:
- OCR + LLM → explicit text, safer
- End-to-end Image QA → opaque, riskier

Use Image QA when:
- layout matters
- text is incidental

## 13. Human Oversight

Image QA should be:
- assistive
- reviewable
- not final authority

Especially in:
- healthcare
- legal
- safety-critical domains

## 14. Anti-Patterns

❌ Treating Image QA as ground truth  
❌ Automating decisions from Image QA  
❌ Ignoring uncertainty  
❌ Over-trusting fluent answers  
❌ No fallback to human review  

## 15. Safe Use Cases

Good:
- exploratory analysis
- accessibility assistance
- content understanding
- human support tools

Bad:
- autonomous decisions
- compliance judgments
- safety enforcement

## Final Mental Lock

Image QA feels like “seeing”.

But it is:
> language conditioned on visual embeddings.

Confidence ≠ correctness.
